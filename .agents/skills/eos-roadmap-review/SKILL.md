# EOS roadmap review

Read AGENTS.md and the live issues, Project fields, dependencies and linked PRs.
The development Project is separate from editorial planning.

1. Distinguish observed state from estimates, unknowns and proposed changes. GitHub read failures are not evidence of an empty backlog or missing relationship.
2. Identify concrete blockers, ambiguous scope, competing implementations and the critical path from actual dependencies.
3. Propose a bounded next step and the decisions needed for readiness. Do not invent iterations, dates, capacity or effort fields that the project does not use.
4. Report meaningful changes and risks concisely, with links to the canonical issues. Do not create a parallel Markdown backlog or routinely duplicate unchanged status.
5. Keep this review read-only. Applying a planning decision needs an actual change request with its scope; do not turn recommendations into automatic Project writes.
